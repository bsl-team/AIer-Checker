核心概念

先理解这些词，再看数字

多套风格
同一学生的文件按 57 个风格轴的分布分组。只有组内足够接近、组间差异足够大时才标记，至少 3 个文件才做稳定判断。
关注等级
高关注 表示同时出现较强信号，建议优先看；建议复核 表示值得抽查；常规 不代表“没有问题”，只表示当前没有触发优先规则。
历史档案一致性
本次提交与本人过去档案的接近程度。档案应当来自往期比赛；若含本次文件，会因自证而虚高。
Jaccard / Containment
都是 0–100% 的结构重合指标。Jaccard 看双方整体重合，Containment 看一方有多少被另一方覆盖；两者都要结合共享 token 数和行段证据看。
跨用户 / 同用户重复
跨用户是不同学生之间的重复，优先复核；同用户是本人多份提交之间的结构重复，可能是模板或复用，也可能是题目本身相似。
行段证据
系统只展示重合片段附近的行号与 token 数，不把整份源码放进报告。证据用于定位，不等于抄袭结论。

三个示例

数字应该怎样读

例 1：一个学生出现 2 组风格
组 A：T1 / T2 组 B：T3 / T4

组内平均 96%，组间平均 54%，组间差异 42%。这说明本次提交内部存在可区分风格，应打开源码核对是否有模板、代写或历史版本混入。

例 2：一对跨用户重复
Jaccard 86% Containment 93% 共享 22 tokens

行段证据显示 User1/T2.cpp 第 12–18 行与 User2/T2.cpp 第 9–15 行重合。先核对题目是否本身包含公共模板，再和学生过程记录对照。

例 3：合并档案
首次建档 4 个样本 合并新比赛 +2 再次保存 +0

“合并”会跳过档案里已经存在的文件路径，所以同一场比赛重复保存不会重复计数。需要完全重建时才选“仅用本次覆盖”。

判定口径与边界

这些限制是设计选择，不是故障

不是 AI 生成概率

“多套风格”只是风格分布差异的统计线索，不能证明使用了 AI。

不是抄袭判决

结构重合可能来自公共模板、题目约束或教学示例，必须人工核对。

样本少时不强判

只有 1–2 个文件时只能提示差异，不能稳定分组；共同特征不足时会显示“证据不足”。

默认只比较同题

避免 T1 与 T4 误配。若题目命名不一致，可在设置里关闭同题限制，但误报会增加。

短提交会被跳过

默认少于 80 token 的提交不参与查重，页面会显示 too-short 告警。

历史档案可能自证

档案包含本次文件时，一致性会虚高；请先用往期比赛建档，再审查本次比赛。

常见问题

先检查这几项，再判断是不是工具出错

为什么查重页没有结果？

先确认“只看跨用户”和最低分过滤是否过严；再看查重告警是否提示 too-short。默认只比较同一题目，如果各学生的文件名不一致，也会没有候选对。

为什么只显示“建议复核”，不直接告诉我是不是 AI？

因为风格特征无法单独证明生成方式。工具把多套风格、历史偏离和重复信号合并成关注等级，只负责排序；AI 使用与抄袭结论必须由教师结合过程性证据判断。

为什么学生显示“未建档”？

档案库里还没有这个学生的历史样本。先扫描往期比赛，在“学生审查”里点“存入档案”，或在“档案库”里批量保存。

“合并”和“仅用本次覆盖”有什么区别？

合并只追加档案中不存在的文件，保留历史样本，适合日常建档；覆盖会丢弃旧样本，只用本次文件重建，适合确认旧档案错误时使用。

怎样更换档案库路径？

在“设置”里填写新的 JSON 路径后重新扫描；也可以在启动服务时用 --store 临时指定。留空则使用默认的 ~/.code-feature/profiles.json。

扫描很慢怎么办？

查重随文件数增长较快。可以先只放本次需要审查的学生，或提高查重灵敏度要求、减少同用户比较；大文件夹建议分批次扫描。

代码会被上传或执行吗？

不会。服务只监听本机，读取教师选择的文件夹和档案库，做静态解析；不联网上传、不运行学生代码，也不在导出的 Markdown 里放完整源码。

隐私与责任

审查数据留在本机。请把风格偏离、重复对和关注等级当作“下一步看哪里”的线索，而不是对学生的结论。涉及学术诚信判断时，应结合题目约束、提交过程、版本记录和当面沟通。
